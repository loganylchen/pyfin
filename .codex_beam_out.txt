   431	def cluster_families(
   432	    read_chains: List[Tuple[Dict, IntronChain]],
   433	    *,
   434	    wobble_bp: int = 6,
   435	    cassette_max_exon_bp: int = 70,
   436	    gtf_variants: Optional[List[Tuple[str, Chain]]] = None,
   437	) -> ClusterResult:
   438	    """Clustering ONLY: group an interval's reads into multi-exon structural families.
   439	
   440	    The clean, single-responsibility clustering step (see the clustering redesign). Unlike
   441	    :func:`cluster_read_chains`, it does NOT fold exact sub-chains, does NOT fold or spatially
   442	    split mono reads, and never rewrites coordinates. It ONLY:
   443	
   444	      1. groups reads by their EXACT intron chain (3' ignored, no snap),
   445	      2. buckets every single-exon (chain-less) read into ``mono_reads`` UNTOUCHED,
   446	      3. union-finds the distinct multi-exon chains into families by wobble / cassette /
   447	         containment (single-linkage; see :func:`_related`),
   448	      4. returns each family's variant chains + a POOLED read set (reads belong to the
   449	         family, not a member) + the per-variant discovery provenance,
   450	      5. (optional) attaches each GTF hypothesis to the single best-related read family as a
   451	         ZERO-read ``gtf_member`` -- NON-BRIDGING (a GTF never merges two read families) and
   452	         never a read-pool source; a GTF matching no read family becomes a GTF-only family.
   453	
   454	    Deterministic: families and their variants are coordinate-sorted; ``mono_reads`` is a
   455	    plain set. Fold, path-completion, and mono resolution are SEPARATE later per-cluster
   456	    steps -- this function makes no structural-collapse or read-ownership decision.
   457	
   458	    Args:
   459	        read_chains: per-read ``(read_dict, IntronChain)`` (read_dict needs "query_name";
   460	            CIGAR-derived chains, used as-is).
   461	        wobble_bp: per-junction tolerance for wobble / cassette / containment joins.
   462	        cassette_max_exon_bp: max skipped-exon length for a cassette join (0 disables).
   463	        gtf_variants: optional annotation hypotheses as ``(gtf_id, intron_chain)`` pairs. Each is
   464	            attached to the single most-related read family (by the same ``_related`` predicate) as a
   465	            zero-read ``gtf_member``; it NEVER bridges two read families and NEVER contributes to a
   466	            ``read_pool``. Mono (empty-chain) GTF entries are ignored here (annotation of single-exon
   467	            transcripts is handled by the later mono finalizer). The read families are formed BEFORE
   468	            attachment, so annotation cannot change read-derived family structure.
   469	
   470	    Returns:
   471	        A :class:`ClusterResult` (multi-exon families + the interval mono bucket).
   472	    """
   473	    # 1. group reads by EXACT chain; single-exon (chain-less) reads -> the mono bucket.
   474	    by_chain: Dict[Chain, Set[str]] = {}
   475	    mono_reads: Set[str] = set()
   476	    for rd, chain in read_chains:
   477	        rid = rd.get("query_name")
   478	        if rid is None:
   479	            continue
   480	        introns = tuple(chain.introns)
   481	        if not introns:
   482	            mono_reads.add(rid)
   483	        else:
   484	            by_chain.setdefault(introns, set()).add(rid)
   485	
   486	    # 2. union-find the distinct multi-exon chains by wobble / cassette / containment.
   487	    #    Sorted vertex order -> deterministic; the resulting partition (connected
   488	    #    components of the symmetric _related graph) is order-independent regardless.
   489	    multi = sorted(by_chain)
   490	    parent: Dict[Chain, Chain] = {c: c for c in multi}
   491	
   492	    def find(x: Chain) -> Chain:
   493	        while parent[x] != x:
   494	            parent[x] = parent[parent[x]]
   495	            x = parent[x]
   496	        return x
   497	
   498	    for i in range(len(multi)):
   499	        for j in range(i + 1, len(multi)):
   500	            a, b = multi[i], multi[j]
   501	            if find(a) != find(b) and _related(a, b, wobble_bp, cassette_max_exon_bp):
   502	                parent[find(a)] = find(b)
   503	
   504	    comps: Dict[Chain, List[Chain]] = {}
   505	    for c in multi:
   506	        comps.setdefault(find(c), []).append(c)
   507	
   508	    # 3. build families: variants coord-sorted, read pool = union of members' reads,
   509	    #    per-variant discovery reads kept as provenance (not final ownership).
   510	    families: List[ChainFamily] = []
   511	    for comp in comps.values():
   512	        variants = sorted(comp)
   513	        pool: Set[str] = set()
   514	        for c in comp:
   515	            pool |= by_chain[c]
   516	        families.append(ChainFamily(
   517	            variants=variants,
   518	            read_pool=pool,
   519	            variant_reads={c: set(by_chain[c]) for c in comp},
   520	        ))
   521	
   522	    # 4. (optional) attach GTF hypotheses to read families -- NON-BRIDGING, zero-read.
   523	    if gtf_variants:
   524	        _attach_gtf_variants(families, gtf_variants, wobble_bp, cassette_max_exon_bp)
   525	
   526	    # Stable, total family order over every family's chains (read variants + gtf members),
   527	    # so GTF-only families (empty ``variants``) also sort deterministically.
   528	    families.sort(key=_family_sort_key)
   529

   123	def _exact_subchain(short: Chain, long_: Chain) -> bool:
   124	    """``short`` is a strict EXACT (identical coords) contiguous sub-chain of ``long_``."""
   125	    n, m = len(long_), len(short)

   131	def _subchain_offset(short: Chain, long_: Chain) -> int:
   132	    """Offset of the first exact ``short`` occurrence in ``long_`` (-1 if none). The
   133	    introns of ``long_`` outside ``[off, off+len(short))`` are the container's EXTRA
   134	    introns relative to ``short`` -- positions where ``short`` splices differently."""
   135	    n, m = len(long_), len(short)
   136	    if m == 0 or m >= n:
   137	        return -1

   139	        if long_[off:off + m] == short:

   144	def _wobble(a: Chain, b: Chain, bp: int) -> bool:
   145	    """Same intron count, every donor/acceptor within ``bp``."""
   146	    if len(a) != len(b):
   147	        return False
   148	    return all(abs(s1 - s2) <= bp and abs(e1 - e2) <= bp
   149	               for (s1, e1), (s2, e2) in zip(a, b))

   152	def _contains(short: Chain, long_: Chain, bp: int) -> bool:
   153	    """``short`` is a strictly-shorter contiguous sub-chain of ``long_`` within ``bp``."""
   154	    n, m = len(long_), len(short)
   155	    if m == 0 or m >= n:
   156	        return False
   157	    for off in range(n - m + 1):
   158	        if all(abs(short[k][0] - long_[off + k][0]) <= bp and
   159	               abs(short[k][1] - long_[off + k][1]) <= bp for k in range(m)):
   160	            return True
   161	    return False

   164	def _cassette(a: Chain, b: Chain, bp: int, max_exon_bp: int) -> bool:
   165	    """``a`` (K introns) is a cassette-skip sibling of ``b`` (K-1 introns): at one
   166	    position ``i`` the two introns ``a[i], a[i+1]`` replace ``b[i]``'s span (outer
   167	    donor/acceptor within bp), the skipped exon between them is < ``max_exon_bp``, and
   168	    every other intron matches within bp."""
   169	    if max_exon_bp <= 0 or len(a) != len(b) + 1:
   170	        return False
   171	    for i in range(len(a) - 1):
   172	        if any(abs(a[k][0] - b[k][0]) > bp or abs(a[k][1] - b[k][1]) > bp
   173	               for k in range(i)):
   174	            continue
   175	        if abs(a[i][0] - b[i][0]) > bp or abs(a[i + 1][1] - b[i][1]) > bp:
   176	            continue
   177	        rest = len(b) - i - 1
   178	        if any(abs(a[i + 2 + k][0] - b[i + 1 + k][0]) > bp or
   179	               abs(a[i + 2 + k][1] - b[i + 1 + k][1]) > bp for k in range(rest)):
   180	            continue
   181	        cas = a[i + 1][0] - a[i][1]
   182	        if 0 < cas < max_exon_bp:
   183	            return True
   184	    return False

   187	def _related(a: Chain, b: Chain, wobble_bp: int, cassette_max_exon_bp: int) -> bool:
   188	    """True iff ``a`` and ``b`` should share a cluster (wobble / cassette / containment)."""
   189	    if _wobble(a, b, wobble_bp):
   190	        return True
   191	    lo, hi = (a, b) if len(a) < len(b) else (b, a)
   192	    if len(lo) < len(hi):
   193	        if _cassette(hi, lo, wobble_bp, cassette_max_exon_bp):
   194	            return True
   195	        if _contains(lo, hi, wobble_bp):
   196	            return True
   197	    return False

   164	def _cassette(a: Chain, b: Chain, bp: int, max_exon_bp: int) -> bool:
   165	    """``a`` (K introns) is a cassette-skip sibling of ``b`` (K-1 introns): at one
   166	    position ``i`` the two introns ``a[i], a[i+1]`` replace ``b[i]``'s span (outer
   167	    donor/acceptor within bp), the skipped exon between them is < ``max_exon_bp``, and
   168	    every other intron matches within bp."""
   169	    if max_exon_bp <= 0 or len(a) != len(b) + 1:
   170	        return False
   171	    for i in range(len(a) - 1):
   172	        if any(abs(a[k][0] - b[k][0]) > bp or abs(a[k][1] - b[k][1]) > bp
   173	               for k in range(i)):
   174	            continue
   175	        if abs(a[i][0] - b[i][0]) > bp or abs(a[i + 1][1] - b[i][1]) > bp:
   176	            continue
   177	        rest = len(b) - i - 1
   178	        if any(abs(a[i + 2 + k][0] - b[i + 1 + k][0]) > bp or
   179	               abs(a[i + 2 + k][1] - b[i + 1 + k][1]) > bp for k in range(rest)):
   180	            continue
   181	        cas = a[i + 1][0] - a[i][1]
   182	        if 0 < cas < max_exon_bp:
   183	            return True
   184	    return False

   187	def _related(a: Chain, b: Chain, wobble_bp: int, cassette_max_exon_bp: int) -> bool:
   188	    """True iff ``a`` and ``b`` should share a cluster (wobble / cassette / containment)."""
   189	    if _wobble(a, b, wobble_bp):
   190	        return True
   191	    lo, hi = (a, b) if len(a) < len(b) else (b, a)
   192	    if len(lo) < len(hi):
   193	        if _cassette(hi, lo, wobble_bp, cassette_max_exon_bp):
   194	            return True
   195	        if _contains(lo, hi, wobble_bp):
   196	            return True
   197	    return False

   200	def _monoexon_in_exon(s: int, e: int, chain: Chain, lo: int, hi: int) -> bool:
   201	    """``[s, e)`` (a single-exon read) lies wholly inside ONE exon of a multi-exon
   202	    candidate whose exonic footprint is ``[lo, hi)`` and whose introns are ``chain``
   203	    (each ``[d, a)`` half-open). True iff the read is within the footprint AND overlaps
   204	    no intron -- i.e. it is a fragment of that candidate's exonic sequence, not an
   205	    intronic feature (a different gene) and not something that crosses a junction."""
   206	    if s < lo or e > hi:
   207	        return False
   208	    for d, a in chain:                       # overlap of [s,e) and intron [d,a)
   209	        if s < a and d < e:
   210	            return False
   211	    return True

   431	def cluster_families(
   432	    read_chains: List[Tuple[Dict, IntronChain]],
   433	    *,
   434	    wobble_bp: int = 6,
   435	    cassette_max_exon_bp: int = 70,

   437	) -> ClusterResult:
   438	    """Clustering ONLY: group an interval's reads into multi-exon structural families.
   439	
   440	    The clean, single-responsibility clustering step (see the clustering redesign). Unlike
   441	    :func:`cluster_read_chains`, it does NOT fold exact sub-chains, does NOT fold or spatially
   442	    split mono reads, and never rewrites coordinates. It ONLY:
   443	
   444	      1. groups reads by their EXACT intron chain (3' ignored, no snap),
   445	      2. buckets every single-exon (chain-less) read into ``mono_reads`` UNTOUCHED,
   446	      3. union-finds the distinct multi-exon chains into families by wobble / cassette /
   447	         containment (single-linkage; see :func:`_related`),
   448	      4. returns each family's variant chains + a POOLED read set (reads belong to the
   449	         family, not a member) + the per-variant discovery provenance,
   450	      5. (optional) attaches each GTF hypothesis to the single best-related read family as a
   451	         ZERO-read ``gtf_member`` -- NON-BRIDGING (a GTF never merges two read families) and
   452	         never a read-pool source; a GTF matching no read family becomes a GTF-only family.
   453	
   454	    Deterministic: families and their variants are coordinate-sorted; ``mono_reads`` is a
   455	    plain set. Fold, path-completion, and mono resolution are SEPARATE later per-cluster
   456	    steps -- this function makes no structural-collapse or read-ownership decision.
   457	
   458	    Args:
   459	        read_chains: per-read ``(read_dict, IntronChain)`` (read_dict needs "query_name";
   460	            CIGAR-derived chains, used as-is).
   461	        wobble_bp: per-junction tolerance for wobble / cassette / containment joins.
   462	        cassette_max_exon_bp: max skipped-exon length for a cassette join (0 disables).
   463	        gtf_variants: optional annotation hypotheses as ``(gtf_id, intron_chain)`` pairs. Each is
   464	            attached to the single most-related read family (by the same ``_related`` predicate) as a
   465	            zero-read ``gtf_member``; it NEVER bridges two read families and NEVER contributes to a
   466	            ``read_pool``. Mono (empty-chain) GTF entries are ignored here (annotation of single-exon
   467	            transcripts is handled by the later mono finalizer). The read families are formed BEFORE
   468	            attachment, so annotation cannot change read-derived family structure.
   469	
   470	    Returns:
   471	        A :class:`ClusterResult` (multi-exon families + the interval mono bucket).
   472	    """

   474	    by_chain: Dict[Chain, Set[str]] = {}
   475	    mono_reads: Set[str] = set()
   476	    for rd, chain in read_chains:
   477	        rid = rd.get("query_name")
   478	        if rid is None:
   479	            continue
   480	        introns = tuple(chain.introns)
   481	        if not introns:
   482	            mono_reads.add(rid)
   483	        else:
   484	            by_chain.setdefault(introns, set()).add(rid)
   485	
   486	    # 2. union-find the distinct multi-exon chains by wobble / cassette / containment.
   487	    #    Sorted vertex order -> deterministic; the resulting partition (connected
   488	    #    components of the symmetric _related graph) is order-independent regardless.
   489	    multi = sorted(by_chain)
   490	    parent: Dict[Chain, Chain] = {c: c for c in multi}
   491	
   492	    def find(x: Chain) -> Chain:
   493	        while parent[x] != x:
   494	            parent[x] = parent[parent[x]]
   495	            x = parent[x]
   496	        return x
   497	
   498	    for i in range(len(multi)):

   505	    for c in multi:

   509	    #    per-variant discovery reads kept as provenance (not final ownership).
   510	    families: List[ChainFamily] = []

   519	            variant_reads={c: set(by_chain[c]) for c in comp},
   520	        ))

   528	    families.sort(key=_family_sort_key)

    30	def extract_diff_regions(
    31	    candidates: List[TranscriptCandidate],
    32	    pad_bp: int = 6,
    33	) -> List[Tuple[int, int]]:
    34	    """Return padded diff regions for SAME-CLASS candidates.
    35	
    36	    Same-class candidates differ only by per-junction wobble (≤ chain_wobble
    37	    bp per donor/acceptor; see :func:`cluster_candidates_by_chain`). This
    38	    function locates each junction-wobble disagreement and returns a genomic
    39	    window that brackets the full affected intron with ``pad_bp`` flanking
    40	    exonic context on both sides.
    41	
    42	    Algorithm:
    43	        1. Build per-base exon/intron labels per candidate.
    44	        2. Find ``diff_mask = exon_any & intron_any`` and segment into raw
    45	           contiguous clusters.
    46	        3. For each raw cluster, take the **union** of every overlapping
    47	           intron interval from any candidate. This grows the window from
    48	           "just the disagreeing bases" to "the entire affected intron".
    49	        4. Pad the union by ``pad_bp`` on each side (clipped to the
    50	           candidate span).
    51	        5. Merge overlapping/adjacent padded windows.
    52	
    53	    **The caller is responsible for passing candidates from the same class.**
    54	    Cross-class structural differences (cassette exons, alt UTRs) are out of
    55	    scope: they are resolved by the chain partition itself, not by signal
    56	    DTW.
    57	
    58	    Per-base labels (internal):
    59	        0 = not covered by the candidate
    60	        1 = exon
    61	        2 = intron
    62	
    63	    Args:
    64	        candidates: List of same-class TranscriptCandidate.
    65	        pad_bp: Flanking exonic context (bp) added to each side of the
    66	            unioned intron window. Default 6.
    67	
    68	    Returns:
    69	        Sorted list of (g_start, g_end) tuples (half-open) in genomic
    70	        coordinates. Empty if fewer than 2 candidates or no disagreement.
    71	    """
    72	    if len(candidates) < 2:
    73	        return []
    74	
    75	    g_lo = min(c.start for c in candidates)
    76	    g_hi = max(c.end for c in candidates)
    77	    if g_hi <= g_lo:
    78	        return []
    79	
    80	    span = g_hi - g_lo
    81	    n = len(candidates)
    82	
    83	    # Per-candidate per-base label array.
    84	    labels = np.zeros((n, span), dtype=np.int8)
    85	    for i, cand in enumerate(candidates):
    86	        c_lo = max(cand.start, g_lo) - g_lo
    87	        c_hi = min(cand.end, g_hi) - g_lo
    88	        if c_hi <= c_lo:
    89	            continue
    90	        labels[i, c_lo:c_hi] = 1  # exon
    91	        for i_start, i_end in cand.intron_chain.introns:
    92	            i_lo = max(i_start, g_lo) - g_lo
    93	            i_hi = min(i_end, g_hi) - g_lo
    94	            if i_hi <= i_lo:
    95	                continue
    96	            labels[i, i_lo:i_hi] = 2  # intron
    97	
    98	    exon_any = (labels == 1).any(axis=0)
    99	    intron_any = (labels == 2).any(axis=0)
   100	    diff_mask = exon_any & intron_any
   101	    if not diff_mask.any():
   102	        return []
   103	
   104	    # Raw diff runs (maximal contiguous bases of exon/intron disagreement).
   105	    raw: List[Tuple[int, int]] = []
   106	    in_region = False
   107	    seg_start = 0
   108	    for i in range(span):
   109	        if diff_mask[i] and not in_region:
   110	            seg_start = i
   111	            in_region = True
   112	        elif not diff_mask[i] and in_region:
   113	            raw.append((seg_start, i))
   114	            in_region = False
   115	    if in_region:
   116	        raw.append((seg_start, span))
   117	
   118	    # For each raw cluster, union all overlapping intron intervals across
   119	    # candidates, then pad ±pad_bp.
   120	    windows: List[Tuple[int, int]] = []
   121	    for lo, hi in raw:
   122	        g_cluster_lo = lo + g_lo
   123	        g_cluster_hi = hi + g_lo
   124	        u_lo = g_cluster_lo
   125	        u_hi = g_cluster_hi
   126	        for cand in candidates:
   127	            for i_s, i_e in cand.intron_chain.introns:
   128	                # Half-open overlap with the raw cluster.
   129	                if i_e > g_cluster_lo and i_s < g_cluster_hi:
   130	                    if i_s < u_lo:
   131	                        u_lo = i_s
   132	                    if i_e > u_hi:
   133	                        u_hi = i_e
   134	        pad_lo = max(g_lo, u_lo - pad_bp)
   135	        pad_hi = min(g_hi, u_hi + pad_bp)
   136	        if pad_hi > pad_lo:
   137	            windows.append((pad_lo, pad_hi))
   138	
   139	    if not windows:
   140	        return []
   141	
   142	    # Merge overlapping/adjacent windows (sorted by start).
   143	    windows.sort()
   144	    merged: List[Tuple[int, int]] = [windows[0]]
   145	    for s, e in windows[1:]:
   146	        prev_s, prev_e = merged[-1]
   147	        if s <= prev_e:
   148	            merged[-1] = (prev_s, max(prev_e, e))
   149	        else:
   150	            merged.append((s, e))
   151	    return merged

    68	    Args:

    70	        gap: Maximum allowed distance from the previous (sorted) position to

    89	def _has_canonical_motif(
    90	    pos: int,
    91	    kind: str,
    92	    strand: str,
    93	    genome_seq: str,
    94	) -> bool:
    95	    """Check whether a donor/acceptor position carries the canonical splice motif.
    96	
    97	    Splice site conventions (0-based, half-open intron [s, e)):
    98	        + strand: donor=GT at genome[s:s+2], acceptor=AG at genome[e-2:e].
    99	        - strand: donor=AC at genome[e-2:e], acceptor=CT at genome[s:s+2].
   100	
   101	    Args:
   102	        pos: For a donor on + strand or acceptor on - strand, this is the
   103	            intron start ``s``. For an acceptor on + strand or donor on -
   104	            strand, this is the intron end ``e``.
   105	        kind: "donor" or "acceptor".
   106	        strand: "+" or "-".
   107	        genome_seq: Full chromosome sequence string.
   108	
   109	    Returns:
   110	        True if the 2 bp motif at the expected offset matches.
   111	    """
   112	    if not genome_seq:
   113	        return False
   114	    n = len(genome_seq)
   115	    if strand == "+":
   116	        if kind == "donor":
   117	            if pos < 0 or pos + 2 > n:
   118	                return False
   119	            return genome_seq[pos:pos + 2].upper() == "GT"
   120	        # acceptor on + strand: pos is intron end e, motif at [e-2, e)
   121	        if pos - 2 < 0 or pos > n:
   122	            return False
   123	        return genome_seq[pos - 2:pos].upper() == "AG"
   124	    # '-' strand
   125	    if kind == "donor":
   126	        # donor on - strand: pos is intron end e, motif at [e-2, e) == "AC"
   127	        if pos - 2 < 0 or pos > n:
   128	            return False
   129	        return genome_seq[pos - 2:pos].upper() == "AC"
   130	    # acceptor on - strand: pos is intron start s, motif at [s, s+2) == "CT"
   131	    if pos < 0 or pos + 2 > n:
   132	        return False
   133	    return genome_seq[pos:pos + 2].upper() == "CT"

   143	
   144	    Priority order (per the junction-snap algorithm):
   145	      1. Most-supported position whose flanking motif is canonical.
   146	      2. Most-supported position overall (mode).

   148	         stable; we additionally pick the median when ties remain).

   177	            if counts[p] * 2 >= top_support:

## B. Recoverability Assumption

“At least one read is correct per junction” is **necessary but substantially insufficient**.

For a raw-coordinate graph, the true recoverability condition is:

1. The truth belongs to the correct read-derived family.
2. For every truth position `i`, at least one observed exact node falls within the evaluation tolerance.
3. There is a **single coordinate-consistent graph path** `v1…vk` such that:
   - `vi` matches truth junction `i` within tolerance.
   - Every exact edge `vi→v(i+1)` was observed consecutively in at least one read.
4. The path is not removed by support guards, beam pruning, candidate caps, or terminal/maximality rules.

The “every adjacency is observed” test must not match each truth adjacency independently. Consider:

- Incoming edge ends at observed wobble node `J`.
- Outgoing edge begins at nearby node `J′`.
- Both independently match the same truth junction within 6 bp.
- But `J != J′`, so there is no continuous raw-node path.

This is especially important because consensus currently permits wobbled partials to connect, as demonstrated at `tests/unit/test_junction_graph.py:67`. Keeping raw nodes preserves coordinate alternatives but can disconnect partial reads that consensus would join.

Thus the exact ceiling should be measured by a **layered path-existence dynamic program**, not separate node and adjacency predicates.

## C. Beam Search

### Recommended score

Use a deterministic lexicographic score rather than one weighted scalar:

1. **Bottleneck edge support:** maximize the minimum read count over path edges.
2. **Transition likelihood:** maximize  
   `Σ log((edge_support + α) / (outgoing_support + α·degree))`.
3. **Cumulative edge support:** maximize `Σ log1p(edge_support)`.
4. **Node support:** maximize the minimum node support, then cumulative node support.
5. **Observed-chain coverage:** prefer paths containing longer contiguous subpaths from individual reads.
6. **Structural tie-break:** lexicographic tuple of genomic junction coordinates.

Bottleneck-first avoids a long path with one extremely dubious bridge beating a uniformly supported path merely because it accumulates more total support. Transition normalization prevents highly covered loci from automatically dominating everything.

Do not use GTF status in the primary beam score for the read-derived graph. Otherwise GTF changes whether a read-derived truth survives generation.

### Recall guarantee

There is **no modest beam width that guarantees survival of the true path** merely because all its edges were observed.

A low-abundance true path can be ranked below arbitrarily many noisy or high-abundance alternatives. A guarantee requires:

- Beam width at least as large as the maximum number of viable prefixes at every expansion layer, or
- Exhaustive enumeration.

That bound is exponential in the number of branches. Therefore “near-certain” must be established empirically:

1. Exhaustively enumerate families whose path count is below a threshold.
2. Measure the true-path rank distribution on truth-matched families.
3. Choose beam width at or above the desired quantile, such as the observed 99.9th percentile.
4. Report oracle recoverability separately from beam-surviving recoverability.

A reasonable experimental starting point is:

- Exhaustive if estimated paths `<=256`.
- Beam width `256` per frontier/layer for larger families.
- Hard emitted additions cap `256` or `512` per family.
- Preserve at least a small quota per distinct first branch and terminal branch so one dominant route cannot consume the entire beam.

These are starting values, not recall guarantees.

### Complexity

For a DAG:

- Graph construction: `O(total observed introns + total observed adjacencies)`.
- Exhaustive enumeration: `O(P·L)`, where `P` is the number of paths and `L` their average length.
- Beam search: approximately `O(L·B·D log(BD))`, where `B` is beam width and `D` maximum outgoing degree.
- Memory: `O(B·L)` with explicit prefixes, reducible using parent pointers.

### Dominance pruning

There is no generally safe support-based dominance rule for structurally different prefixes in a recall-first generator. A weaker-supported prefix may be the true minor isoform.

Safe cheap pruning is limited to:

- Deduplicate the exact same structural partial path.
- Merge duplicate derivations of that path while unioning provenance.
- Remove graph-invalid paths, cycles, non-monotonic introns, or incompatible site reuse.
- Optionally merge states only when they have identical structural prefix and identical future compatibility state.

Do not drop one coordinate-distinct path merely because it ends at the same node with lower support.

“All variants are kept” must mean **all beam survivors are kept**. Beam pruning necessarily means not all graph paths are kept.

## D. Combinatorial Safety

Confirm these two protections:

- An intron node must remain an observed paired `(donor, acceptor)` coordinate. Never independently combine donor and acceptor alternatives; the prior code explicitly identifies that Cartesian bug at `fin/candidates/intron_chains.py:399`.
- An edge exists only when one read contains the two exact intron nodes consecutively, matching the current contract at `fin/candidates/junction_graph.py:54`.

Add these guards:

1. **Valid-chain geometry:** enforce genomic ordering and require the exon between consecutive introns to have positive length.
2. **Same-site exclusivity:** define near-equivalent junction-site groups and forbid one path from visiting two variants of the same biological slot.
3. **No cycles or repeated nodes.**
4. **Family-local only:** never assemble across `ChainFamily` boundaries.
5. **Single-linkage bridge audit:** `cluster_families()` uses connected components of `_related`, including wobble, cassette, and containment relations at `fin/candidates/chain_cluster.py:187` and `fin/candidates/chain_cluster.py:486`. A chain of pairwise relations can produce a family whose endpoints are not directly related. Before assembly, split or block graph components whose genomic footprint/site correspondence is inconsistent with a common anchor.
6. **Read-subpath compatibility score:** track the longest contiguous portion supported by one read and penalize paths composed entirely of short, unrelated two-edge fragments.
7. **Global recombination tag:** record whether any single read supports the whole path, whether multiple reads tile it without branch switching, and the number of read handoffs.
8. **Candidate cap:** cap assembled additions, not baseline exact variants.

For a pure recall oracle, use edge threshold `N=1`. Requiring rarest-edge support `>=2` improves precision but changes the recoverable ceiling and can delete a real low-support transcript. Pyfin already has a downstream novel-junction support gate, defaulting to two reads, at `fin/pipeline/config.py:368`. Generation should retain one-read edges and expose their support rather than duplicating that precision decision prematurely.

A stricter optional mode may require `min_edge_support >=2`, but it should not be the recall-mode default.

## E. GTF Junctions

The safest form is **not to put arbitrary GTF nodes or GTF edges into the read graph**.

Bare GTF nodes with no edges cannot participate in assembled paths. Adding GTF transcript adjacency edges injects annotation structure and allows a path to exist without read-phased adjacency, violating the graph’s core contract.

The existing `cluster_families()` design is already safer:

- GTF transcripts are complete, zero-read hypotheses.
- They attach to only one read family.
- They never bridge read families.
- They never enter `read_pool` or `variant_reads`.

That contract is documented at `fin/candidates/chain_cluster.py:394`, implemented at `fin/candidates/chain_cluster.py:409`, and tested against bridging at `tests/unit/test_cluster_families.py:216`.

Recommended behavior:

- Keep each complete GTF transcript as an additive candidate.
- Keep all raw read-derived variants unchanged.
- Do not add GTF-only graph edges.
- At p00, no GTF means byte-identical read-only assembly.

If you specifically want a read-derived path at exact GTF coordinates, use a separate, explicitly tagged **coordinate-substitution hypothesis**:

- A GTF junction may substitute for one observed node only when both boundaries are within tolerance.
- Clone only the incident edges already supported by reads at the observed node.
- Do not add edges merely because two junctions are consecutive in GTF.
- Constrain substitutions to one named GTF transcript per candidate; do not mix junctions from unrelated GTF transcripts.
- Keep the original raw-coordinate path alongside it.
- Tag it `gtf_coordinate_substitution`, not plain `novel`.

That is still annotation-assisted generation, but additive and reversible—not snap or replacement.

## C. Beam Search

### Recommended score

Use a deterministic lexicographic score rather than one weighted scalar:

1. **Bottleneck edge support:** maximize the minimum read count over path edges.
2. **Transition likelihood:** maximize  
   `Σ log((edge_support + α) / (outgoing_support + α·degree))`.
3. **Cumulative edge support:** maximize `Σ log1p(edge_support)`.
4. **Node support:** maximize the minimum node support, then cumulative node support.
5. **Observed-chain coverage:** prefer paths containing longer contiguous subpaths from individual reads.
6. **Structural tie-break:** lexicographic tuple of genomic junction coordinates.

Bottleneck-first avoids a long path with one extremely dubious bridge beating a uniformly supported path merely because it accumulates more total support. Transition normalization prevents highly covered loci from automatically dominating everything.

Do not use GTF status in the primary beam score for the read-derived graph. Otherwise GTF changes whether a read-derived truth survives generation.

### Recall guarantee

There is **no modest beam width that guarantees survival of the true path** merely because all its edges were observed.

A low-abundance true path can be ranked below arbitrarily many noisy or high-abundance alternatives. A guarantee requires:

- Beam width at least as large as the maximum number of viable prefixes at every expansion layer, or
- Exhaustive enumeration.

That bound is exponential in the number of branches. Therefore “near-certain” must be established empirically:

1. Exhaustively enumerate families whose path count is below a threshold.
2. Measure the true-path rank distribution on truth-matched families.
3. Choose beam width at or above the desired quantile, such as the observed 99.9th percentile.
4. Report oracle recoverability separately from beam-surviving recoverability.

A reasonable experimental starting point is:

- Exhaustive if estimated paths `<=256`.
- Beam width `256` per frontier/layer for larger families.
- Hard emitted additions cap `256` or `512` per family.
- Preserve at least a small quota per distinct first branch and terminal branch so one dominant route cannot consume the entire beam.

These are starting values, not recall guarantees.

### Complexity

For a DAG:

- Graph construction: `O(total observed introns + total observed adjacencies)`.
- Exhaustive enumeration: `O(P·L)`, where `P` is the number of paths and `L` their average length.
- Beam search: approximately `O(L·B·D log(BD))`, where `B` is beam width and `D` maximum outgoing degree.
- Memory: `O(B·L)` with explicit prefixes, reducible using parent pointers.

### Dominance pruning

There is no generally safe support-based dominance rule for structurally different prefixes in a recall-first generator. A weaker-supported prefix may be the true minor isoform.

Safe cheap pruning is limited to:

- Deduplicate the exact same structural partial path.
- Merge duplicate derivations of that path while unioning provenance.
- Remove graph-invalid paths, cycles, non-monotonic introns, or incompatible site reuse.
- Optionally merge states only when they have identical structural prefix and identical future compatibility state.

Do not drop one coordinate-distinct path merely because it ends at the same node with lower support.

“All variants are kept” must mean **all beam survivors are kept**. Beam pruning necessarily means not all graph paths are kept.

## D. Combinatorial Safety

Confirm these two protections:

- An intron node must remain an observed paired `(donor, acceptor)` coordinate. Never independently combine donor and acceptor alternatives; the prior code explicitly identifies that Cartesian bug at `fin/candidates/intron_chains.py:399`.
- An edge exists only when one read contains the two exact intron nodes consecutively, matching the current contract at `fin/candidates/junction_graph.py:54`.

Add these guards:

1. **Valid-chain geometry:** enforce genomic ordering and require the exon between consecutive introns to have positive length.
2. **Same-site exclusivity:** define near-equivalent junction-site groups and forbid one path from visiting two variants of the same biological slot.
3. **No cycles or repeated nodes.**
4. **Family-local only:** never assemble across `ChainFamily` boundaries.
5. **Single-linkage bridge audit:** `cluster_families()` uses connected components of `_related`, including wobble, cassette, and containment relations at `fin/candidates/chain_cluster.py:187` and `fin/candidates/chain_cluster.py:486`. A chain of pairwise relations can produce a family whose endpoints are not directly related. Before assembly, split or block graph components whose genomic footprint/site correspondence is inconsistent with a common anchor.
6. **Read-subpath compatibility score:** track the longest contiguous portion supported by one read and penalize paths composed entirely of short, unrelated two-edge fragments.
7. **Global recombination tag:** record whether any single read supports the whole path, whether multiple reads tile it without branch switching, and the number of read handoffs.
8. **Candidate cap:** cap assembled additions, not baseline exact variants.

For a pure recall oracle, use edge threshold `N=1`. Requiring rarest-edge support `>=2` improves precision but changes the recoverable ceiling and can delete a real low-support transcript. Pyfin already has a downstream novel-junction support gate, defaulting to two reads, at `fin/pipeline/config.py:368`. Generation should retain one-read edges and expose their support rather than duplicating that precision decision prematurely.

A stricter optional mode may require `min_edge_support >=2`, but it should not be the recall-mode default.

## E. GTF Junctions

The safest form is **not to put arbitrary GTF nodes or GTF edges into the read graph**.

Bare GTF nodes with no edges cannot participate in assembled paths. Adding GTF transcript adjacency edges injects annotation structure and allows a path to exist without read-phased adjacency, violating the graph’s core contract.

The existing `cluster_families()` design is already safer:

- GTF transcripts are complete, zero-read hypotheses.
- They attach to only one read family.
- They never bridge read families.
- They never enter `read_pool` or `variant_reads`.

That contract is documented at `fin/candidates/chain_cluster.py:394`, implemented at `fin/candidates/chain_cluster.py:409`, and tested against bridging at `tests/unit/test_cluster_families.py:216`.

Recommended behavior:

- Keep each complete GTF transcript as an additive candidate.
- Keep all raw read-derived variants unchanged.
- Do not add GTF-only graph edges.
- At p00, no GTF means byte-identical read-only assembly.

If you specifically want a read-derived path at exact GTF coordinates, use a separate, explicitly tagged **coordinate-substitution hypothesis**:

- A GTF junction may substitute for one observed node only when both boundaries are within tolerance.
- Clone only the incident edges already supported by reads at the observed node.
- Do not add edges merely because two junctions are consecutive in GTF.
- Constrain substitutions to one named GTF transcript per candidate; do not mix junctions from unrelated GTF transcripts.
- Keep the original raw-coordinate path alongside it.
- Tag it `gtf_coordinate_substitution`, not plain `novel`.

That is still annotation-assisted generation, but additive and reversible—not snap or replacement.

## F. Measure First

Run this analysis over missed `FL>=3` truth, both overall and split into the stated 74% truncated and 10% wobble categories:

1. **Exact baseline recoverable:** some observed family variant already matches the full truth chain.
2. **Node-covered:** every truth junction has at least one family node within 6 bp.
3. **Pairwise-edge-covered:** every truth adjacency has at least one read-backed observed edge matching its two truth junctions within 6 bp.
4. **Consistent-path-covered:** layered DP finds one continuous raw-node path through all truth positions.
5. **Boundary-emittable:** that path is eligible under terminal/maximal/TSS rules.
6. **Support-surviving:** path remains with each proposed minimum-edge threshold.
7. **Beam-surviving:** path rank survives widths `16, 32, 64, 128, 256, 512`.
8. **Cap-surviving:** path is present after the proposed per-family emitted-candidate cap.

The critical oracle is step 4, not merely steps 2–3.

Report:

- Fraction of all missed truth at each stage.
- Increment over exact-chain baseline.
- Distribution of true-path beam rank.
- Candidate additions per family.
- Number of graph paths versus truth-recoverable paths.
- Fraction of emitted paths fully observed by one read, tiled without a branch switch, and globally recombinant.
- Results separately for p00 and GTF-present scenarios.

This gives both the theoretical raw-graph ceiling and the practical beam/cap ceiling before implementation.

## Final Algorithm

1. Route production through `cluster_families()` rather than the older `cluster_read_chains()` path.
2. Always emit every exact observed family variant.
3. Per family, create one node for every exact observed intron coordinate.
4. Build edges only from exact consecutive introns within a single read; store supporting read-ID sets.
5. Validate order, exon length, site exclusivity, and family/locus consistency.
6. Enumerate coordinate-resolved, boundary-valid paths:
   - Exhaustively below a path-count threshold.
   - Deterministic bottleneck-first beam above it.
7. Deduplicate exact structures and retain all surviving additions up to a configurable family cap.
8. Never let the cap remove baseline exact-chain or complete GTF candidates.
9. Keep complete GTF transcripts as zero-read additive family members.
10. Optionally emit separately tagged GTF-coordinate substitutions using cloned read-derived edges, never GTF-only adjacency edges.
11. Defer minimum-support and TP/FP decisions downstream.

Do not overload `TranscriptCandidate.source`: downstream currently expects `"gtf"`, `"novel"`, or `"fusion"` at `fin/candidates/dataclasses.py:44`. Add a provenance field or `CandidateSet` sidecar containing:

- `generation_origin`: `exact_read_chain`, `graph_assembled`, `gtf_full_chain`, or `gtf_coordinate_substitution`
- Node and edge support counts/read IDs
- Parent exact variants
- Number and locations of read handoffs
- `whole_chain_read_observed`
- `global_phase_observed`
- Beam score/rank and whether enumeration was capped
- GTF transcript ID, if applicable
- `additive_reversible=True`

Here, reversible means the original exact read variants remain available and disabling graph assembly removes only additive assembled hypotheses. This is the design I recommend.
