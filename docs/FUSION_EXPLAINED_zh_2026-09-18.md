# Fusion 流水线：从一条 RNA 分子的解释，到融合转录本模型

这份讲解以当前 `fin/fusion/` 的实际代码和 K562 冻结产物为准；全程只读，没有修改文件。两个算法问题也分别核对了源码、最小复现和逐分子结果。

先把最重要的一点说清楚：

**这个流水线不是“看到一条 read 同时比到两个基因，就宣布发现融合”。它试图先回答：这条 RNA 分子有哪些合理解释，跨基因的解释是否站得住；然后才把多条分子的证据汇集成融合转录本模型。**

BCR–ABL1 是这条链路的阳性例子；BAG6–SLC44A4 暴露的是“事件有支持，但具体坐标和模型划分还不够可靠”；chrM 则提醒我们，**跨越参考坐标的不连续，不一定意味着生物学上的异常连接。**

---

## 一、这个 fusion 流水线到底在做什么：从 BAM 到 FASTA

### 1. 先分清三个层次：分子、连接结构、转录本模型

可以把整个流程理解成三层问题：

| 层次 | 在问什么 | BCR–ABL1 的例子 |
|---|---|---|
| 单分子解释 | 这一条 read 到底来自什么 RNA 结构？有没有正常比对的替代解释？ | 这条 read 是否真的跨过 BCR→ABL1，而不只是 BCR 加一段错误匹配的尾巴？ |
| 分子间汇集 | 多条不同 read 是否支持同一条有顺序的连接路径？ | 是否有多条分子支持 BCR 在前、ABL1 在后，以及相容的结点和剪接结构？ |
| 转录本模型 | 这些分子合起来支持什么外显子结构？每个基因臂兼容哪些异构体？序列是什么？ | 是 `BCR:e14>ABL1:e2`，兼容哪些 ENST，能输出多长的序列？ |

这里所谓“一条分子”，在程序里主要以 **read ID** 为单位。一个 read 的 primary、supplementary、secondary alignment，不是三条独立分子，不能算三票。

还要注意：这是普通转录本组装之外的一条独立分析路径，不是把 fusion 候选塞进普通组装的 EM，再靠表达量竞争决定它是否存在。独立性的目的，是避免打开 fusion 功能后，普通组装结果也跟着改变。

### 2. BAM 扫描：先提名值得进一步检查的分子

入口是 `input.scan_fusion_bam`。

它首先问：

> 这个 BAM 里，哪些分子有理由怀疑不能用一个普通的单基因转录本解释？

主要提名线索包括：

- 有 supplementary alignment 或 `SA` 标签；
- 有达到阈值的大段 clipping，目前阈值是 250 bp；
- 一条剪接比对跨过了不同基因的注释区域。

**提名不是通过。** 提名更像“把这条分子送去进一步检查”。

例如：

- **BCR–ABL1**：一个部分落在 chr22 的 BCR，另一部分落在 chr9 的 ABL1，会进入候选。
- **BAG6–SLC44A4**：同在 chr6，不意味着正常；仍要检查连接顺序、链方向和跨基因结构。
- **chrM**：跨过线性参考的末端与开头，也可能被表现成 split alignment，因此会被提名；此时还不能说它是异常融合。

提名后，程序再收集这些 read 的相关比对记录，包括正常比对和其他位置的替代比对。BAM 中序列不足时，可以从配套 FASTQ 补齐并核对。

所以，后面处理的是“一个 read 的整套证据”，不是只挑那个最像融合的 supplementary record。

源码入口：`fin/fusion/input.py:59`、`fin/fusion/input.py:99`。

### 3. 全基因组重比对：不能只在怀疑的两个基因附近找答案

接下来是 `realignment.map_many`。

这一步问：

> 如果不预先相信 BAM 已经给出的融合解释，把整条 read 和未解释的部分重新放回全基因组，它们还可能来自哪里？

这对精度非常重要。

假设一条 read 看起来是 BCR→ABL1，但其实：

- 有一个正常基因位置能解释绝大多数序列；
- 或者另一个同源区域能提供几乎同样好的解释；
- 或者所谓的“第二个融合臂”只是错误匹配。

如果只对 BCR 和 ABL1 建小参考，这些替代解释根本没有出场机会。

因此，K562 的全库验证比只跑 chr9、chr22 的小型 fixture 更有意义：**BCR–ABL1 是在全基因组竞争背景下找出来的，不是事先告诉程序只看这两个基因。**

这里还会保留低 MAPQ 的替代位置进入竞争，而不是先扔掉它们，再把剩下的融合解释当成唯一答案。最终能否给出支持结论，是后面的事情。

对应代码：`fin/fusion/realignment.py:58`。

### 4. 处理 SA：定位摘要不能冒充完整的剪接结构

接下来是 `records.reconcile_sa_locators`。

这一步解决一个在真实 BCR–ABL1 数据中遇到过的问题：

**SA 标签有时只保留一个简化的定位摘要，不是原始剪接比对的完整 CIGAR。**

真实数据里曾出现 `175M723D` 这样的摘要。如果把它完全按字面当作精细结构，程序可能认为模板里有一大段需要保留的参考序列，而实际详细比对显示的是剪接结构。

可以把它类比成：

> SA 是“这段 read 大概在这栋楼里”的地址条；详细 alignment 才是“从哪一层、哪一间房经过”的路线图。

有详细比对能证实同一位置时，程序用详细结构取代那个 SA 摘要。它不是直接把大 deletion 改成 intron，因为摘要已经丢掉的信息不能凭空补回来。

这个修复曾是让真实 BCR–ABL1 从“找不到或找错”变成正确模型的重要环节。

对应代码：`fin/fusion/records.py:247`。

### 5. 路径枚举：一条分子可能有不止一种解释

然后是 `paths.find_read_paths`。

这一步尝试把 alignment segments 按 read 上的先后顺序串起来，问：

> 哪些片段组合，可以解释这条 read 的足够大一部分？

这里的“路径”不是基因组上的一条固定线路，而是**对同一条 read 的一种解释**。

例如一条看似 BCR–ABL1 的 read，理论上可能存在：

1. BCR→ABL1 的两臂解释；
2. 只来自一个正常位点、末端有少量未解释序列的解释；
3. BCR→某个同源区域的替代解释；
4. 相同基因顺序、但结点相差几 bp 的几种解释。

这些解释相互竞争，因为它们解释的是**同一条序列**，不是不同分子。

覆盖度通常要求达到 0.9，但这里还有一个真实 dRNA 数据需要的细节：对于所有详细基因组比对都无法放置的、受严格长度限制的末端序列，可以从覆盖度分母中排除。这样，约几十 bp 的非基因组末端不会机械地毁掉一条真实 BCR–ABL1 read。

但是：

- 不能随便排除内部缺口；
- 不能把已经能比到第二个位点的末端当作 adapter 扔掉；
- 不能为了某个融合假设单独缩小分母。

**当前这一环节存在“合格正常路径丢失”的问题，第三节会展开。** 因而，“枚举所有合理解释”是设计目标，还不是当前实现完全兑现的保证。

对应代码：`fin/fusion/paths.py:85`、`fin/fusion/paths.py:115`。

### 6. 按基因标签切臂：先描述结构，再谨慎命名

`annotation.annotate_read_path` 把路径上的连续片段按基因标签划分成“臂”。

一条臂可以包含多个外显子，不等于一个 alignment record，也不等于一个外显子。

例如：

- BCR 的若干外显子组成第一臂；
- ABL1 的若干外显子组成第二臂；
- 三基因或带未注释中间片段的结构，可以有三臂以上。

程序根据染色体、链方向、顺序和距离给出结构分类：

- BCR→ABL1：跨 chr22 和 chr9，是 `interchromosomal_candidate`。
- 同一染色体、同方向、顺着转录方向且在距离范围内的连接：可以标成 `readthrough_or_splicing_candidate`。
- 不满足这些条件的同染色体连接：可能是 `intrachromosomal_candidate`。

**BAG6–SLC44A4 是不能只看基因名字和邻近关系的例子。**

当前代表结点是：

```text
chr6:31651655:- → chr6:31865784:-
```

两臂都是负链，但连接时坐标向上跳。负链的正常转录方向是向较小坐标推进，因此这个连接不能简单解释成“邻居基因之间顺着读过去”。

程序把它列为染色体内候选，而不是普通 readthrough。旧文字里把它笼统称作 MHC 区 readthrough 的说法不应继续沿用。

同理，chrM 的末端→开头在线性坐标上“不顺”，但在环状参考上可能恰好是连续的。**结构分类必须考虑参考拓扑，而不能只看坐标大小。**

对应代码：`fin/fusion/annotation.py:141`。

### 7. 局部结点校正：在附近找更合理的位置，但不能凭注释直接吸附

接下来是 `correction` 和 `junctions`。

这一步不只处理两个基因之间的融合结点，也处理各臂内部的剪接结点。

它问：

> 观察到的结点可能偏了几 bp。附近有没有更能解释 read 序列的位置？

当前默认在每个分子自己的观测位置附近 **±3 bp** 提名候选。候选来源可以是：

- 原始观测位置；
- 其他 read 支持的位置；
- 注释位置；
- 可选的普通组装结点证据；
- 附近具有相应剪接 motif 的位置。

注意，±3 bp 是提名范围，不意味着把范围内所有坐标组合都无条件纳入。

提名之后，程序用**同一条 read 上固定的一段 query 窗口**比较候选模板，做 DP 打分。默认左右 flank 是 35 bp。

固定 query 窗口很重要：不能让 A 候选只解释容易的 50 个碱基，B 候选却必须解释含错误的 70 个碱基，然后直接比两者分数。

对 BCR–ABL1，这一步是在比较：BCR 末端和 ABL1 起点落在哪里，才能更好解释跨结点的实际序列。

对 BAG6–SLC44A4，问题正出在这里：**不同分子的候选范围不同，有些分子根本没有比较过另一个模型的坐标。** 这不是把分数阈值稍微调高就能解决的。

对应代码：`fin/fusion/junctions.py:88`、`fin/fusion/junctions.py:143`。

### 8. 什么是 stitched template：把一种解释真正拼成序列，再问 read 是否支持它

局部结点评分之后，进入 `validation.validate_stitched_path`。

所谓 **stitched template**，就是：

> 按某一种候选路径，把各臂的参考外显子序列按转录方向依次拼起来，形成这条 RNA 假设应当具有的连续序列。

对 BCR–ABL1，就是类似：

```text
BCR 保留部分的外显子序列 | ABL1 保留部分的外显子序列
```

中间的竖线代表候选融合结点，模板本身是连续序列。

然后把真实 read 重新比到这个模板上，检查：

- 是否有同一个正向 alignment 支持整个模板解释；
- 每个外显子连接、融合连接两侧是否有足够的锚定；
- 每个模板 block 是否真的被 read 代表；
- 整体覆盖度、identity 和 indel 是否符合要求。

为什么局部 DP 后还要做这一步？

因为“每个接头单独看都像能接上”，不等于“整条 RNA 拼起来确实成立”。

真实 BCR–ABL1 的早期错误就说明了这一点：一个误带约 700 bp 内含子序列的模板，不能因为 read 只比到其余部分，就被宣布验证通过。现在要求每个模板 block 都被代表，正是为了堵住这种漏洞。

同样，BAG6 的几个局部候选必须放回完整路径验证；chrM 的拼接模板即使很好地解释了 read，也仍不能单凭这一点判断它是异常重排——跨原点的正常环状参考连续性也能产生好模板。

对应代码：`fin/fusion/validation.py:28`、`fin/fusion/validation.py:76`。

### 9. 每条分子的裁决：不是“融合模板能比上”，而是“它有没有同样好的竞争者”

`analysis` 把同一条分子的完整候选解释放在一起比较。

这里要明确区分两个问题：

1. **这个融合模板能解释 read 吗？**
2. **它比非融合或其他融合解释更有说服力吗？**

只回答第一个问题，很容易产生假阳性。

例如：

> 一条 1000 bp read，正常位置解释了 950 bp；再从另一个染色体找来一个 50 bp 匹配，拼成两臂模板也能比上。  
> 这不能自动说明跨染色体融合成立。

正常比对必须参加竞争。当前代码也有这样的裁决逻辑：

- 如果竞争者都是正常单臂解释，判为 `not_fusion`；
- 如果正常解释和融合解释都在竞争范围内，保持 `unresolved`；
- 不同基因路径、不同剪接路径或相距较远的坐标解释不能分开时，也保持未决。

只有通过这些判断，才会得到 **`supported_path`**。

它的准确含义是：

> 在当前已经枚举和检验过的假设集合中，这条分子支持某个多臂路径；如果还有局部坐标歧义，这个歧义可以被保留。

因此：

**`supported_path` 不等于“精确断点已确定”，更不等于“DNA 融合已证实”。**

BAG6 的两条问题分子就是直接例子：它们的状态都是 `supported_path`，理由却是 `coordinate_ambiguity`。

对应代码：`fin/fusion/analysis.py:223`。

### 10. 从分子到 chain：谁支持同一条有顺序的连接结构？

`chains.build_fusion_chains` 开始跨分子汇集证据。

它关心：

> 哪些不同 read 支持相同的有序基因臂、内部剪接结构和相近的结点？

这里不是简单按“基因 A–基因 B”分组。内部剪接模式、臂顺序也参与结构区分。

默认 `min_support=2`，意味着支持门槛需要至少两条不同分子。但有一个容易误读的细节：

**函数也保留支持不足的 chain 作为结果记录，而不是只返回达到两条支持的 chain。**

因此“595 chains”并不等于“595 个达到两分子支持的融合事件”。

此外，完整路径支持和部分支持分开：

- 一条分子跨过 BCR→ABL1，可以支持这个两臂连接；
- 对三臂路径 A→B→C，只分别见到 A→B 和 B→C，不能拼凑成有完整分子支持的 A→B→C。

对应代码：`fin/fusion/chains.py:64`。

### 11. chain 和 transcript model 的区别：从“连接证据”到“可解释的转录本结构”

**Chain 更接近分子证据的分组；transcript model 更接近下游研究者要使用的 RNA 结构。**

长读长 dRNA 有一个实际问题：同一融合的不同分子可能从不同位置开始，有的少了若干 5′ 外显子，有的只少了一段首外显子。

因此，同一个 BCR–ABL1 转录本的 read，可能被细分在不同 chain 中。不能因为每条 chain 各只有一条 read，就完全丢掉它们共同支持的融合结构。

`transcript_models` 会进一步：

- 比较外显子结构；
- 处理相容的 5′/3′ 截短；
- 汇集成有明确外显子范围的模型；
- 按每一臂的观测剪接结构寻找兼容的 ENST；
- 记录哪些 read 唯一支持、哪些只兼容、哪些只是部分支持或附近证据。

对于 BCR–ABL1，这一层才给出：

```text
BCR:e14>ABL1:e2
BCR 兼容哪些 ENST
ABL1 兼容哪些 ENST
模型长度 7172 bp
```

`arm_fsm` 也要正确理解：它表示**融合中保留下来的这一臂，其剪接结构与兼容注释相符**，不是说完整的野生型 BCR 和完整的野生型 ABL1 都被观察到了。

模型还区分：

- `single_molecule_spanned`：至少有一条分子的观测范围达到模型两端；
- `aggregate`：模型两端来自多条分子的联合覆盖，不保证某一条 read 单独覆盖整个模型。

当前 BCR–ABL1 是前者；BAG6 三行里则同时存在这两种情况。

对应代码：`fin/fusion/transcript_models.py:212`、`fin/fusion/transcript_models.py:616`。

### 12. 为什么有两个模型 FASTA？

这里的两个文件，是两个不同证据等级的产品。

| 文件 | 含义 | 不能把它当成什么 |
|---|---|---|
| `fusion_models.fa` | 按分子证据约束的结构，从参考基因组投影出来的序列 | 不是样本逐碱基 consensus，也不保证天然 RNA 两端完整 |
| `fusion_models.annotated.fa` | 在注释允许且兼容结构一致时，对外侧臂做注释补全 | 补出来的部分不是 read 观测事实 |

例如，一条 BCR–ABL1 read 的 BCR 5′ 端缺了一截：

- evidence-constrained 版本只表达证据支持到哪里；
- annotated 版本可以提出“如果沿兼容注释延伸，可能是这样的完整端部”。

两者必须分开，不能悄悄补长后还说整条序列都被实验观察到了。注释补全记录带有 `extension_observed=false`，ID 也与观测版本不同。

**不是每个模型都有 annotated completion。** 当前这个 7172 bp 的 BCR–ABL1 模型没有对应的注释补全记录，5′ 完整性仍标为未知。

而且两个 FASTA 都以参考序列为基础：read 中的样本特异 substitution、insertion 并没有被重建进去。

## 二、K562 真实数据上得到了什么？

### 1. 先看整体漏斗，但不要把它误读成“逐级真阳性筛选”

全库结果是：

```text
1,074,197 条 BAM alignment records
                 ↓
23,403 条被提名的候选分子
                 ↓
595 个 chain 记录
                 ↓
69 个融合转录本模型
```

69 个模型的结构分类为：

| 分类 | 模型数 |
|---|---:|
| `readthrough_or_splicing_candidate` | 48 |
| `intrachromosomal_candidate` | 19 |
| `interchromosomal_candidate` | 2 |

其中 4 个模型有三个臂。

这里有两点需要强调。

第一，起点是 **alignment records**，下一层是 **read ID 去重后的候选分子**，分母单位变了。

第二，595 个 chain 中，冻结表里有 **533 个标为 `insufficient_full_chain_support`**。所以不能把 595 当作经过最低支持过滤的事件数；模型层还会利用截短相容性重新汇集证据。

这也是为什么输出不应该只拿某一层的行数当“融合数量”。

### 2. BCR–ABL1：确实通过了一个有分量的阳性对照

支持最高的染色体间模型是：

```text
BCR:e14>ABL1:e2
chr22:23290413:+ → chr9:130854063:+
support_unique = 4
arm_fsm / arm_fsm
7172 bp
single_molecule_spanned
```

兼容转录本列表为：

- BCR：`ENST00000305877.13`、`ENST00000359540.7`
- ABL1：`ENST00000318560.6`、`ENST00000372348.9`

“ENST 正确”在这里应理解为：**找到了与保留臂结构相符的兼容转录本集合**，不是强行把每个基因唯一解析成一个 ENST。

我也核对了序列一致性：

- 外显子表有 24 个外显子片段，跨 chr22 和 chr9；
- 长度相加为 7172 bp；
- `fusion_models.fa` 中该记录也是 7172 bp。

为什么这算通过阳性对照？

因为它不只是输出了一行“BCR–ABL1”，而是同时回答对了几个层次的问题：

- 在整条真实文库里找到了这个事件；
- 使用全基因组参考，而不是预先限制两个位点；
- 基因顺序正确；
- 得到预期的 e14a2，即 `BCR:e14>ABL1:e2`；
- 两臂的剪接结构与相应注释相符；
- 有四条不同分子支持；
- 外显子表、模型长度和 FASTA 自洽。

这证明了：**整条工程链路能够在真实、带错误和截短的 dRNA 数据中恢复一个已知目标。**

但它没有证明所有坐标细节都唯一确定。冻结模型的 `coordinate_status` 仍是 `unresolved_nearby_placements`。代表结构正确，和所有局部位置都无歧义，是两回事。

冻结记录：`experiments/fusion/_k562_rep4_seq/fusion/fusion_models.tsv:23`。

### 3. 它不能说明什么：不是精度估计，也不是全库真实性证明

BCR–ABL1 找对了，不能推出：

- 剩下 68 个模型都是真的；
- 全库 precision 很高；
- 漏检率很低；
- 支持四条分子就普遍足够可靠；
- 所有模型的精确结点都已确定；
- 找到 RNA 嵌合结构就证明对应 DNA 重排；
- 可以据此判断新事件是否有功能或驱动意义。

原因很简单：我们知道一个阳性目标，不等于知道全库每个候选的真伪。

**BAG6–SLC44A4** 正好说明“基因名和外显子名看起来合理”并不足够。它有三行模型，但坐标竞争并未在所有分子之间公平完成，不能说三行就代表三个真实事件或三个已证实异构体。

**chrM** 则说明支持度高也不等于异常程度高：全库支持最高的两个模型有 390 和 91 条分子，但它们位于参考原点两侧，更应该先问参考线性化如何解释它们。

所以，这次 K562 结果是**阳性对照和端到端可用性证据**，不是全库精度验证。

## 三、2026 年 9 月 18 日算法讨论中的两个真实问题

## 1. `find_read_paths` 的“假设丢失”：正常解释在裁决前就消失了

### 现象是什么？

最小例子是一条 1000 bp read。

先只提供一个 alignment：

```text
chr1: 950M50S
```

含义是：

- 前 950 bp 比到 chr1；
- 后 50 bp 未被这个 alignment 解释。

覆盖度是 0.95，超过 0.9 门槛。程序返回：

```text
chr1
```

现在给同一条 read 再加一个尾部 alignment：

```text
chr2: 950S50M
```

它只解释末端 50 bp。

此时至少有两种应当交给下游比较的解释：

```text
解释 A：chr1，覆盖 0.95
解释 B：chr1 → chr2，覆盖 1.00
```

但是当前函数只返回：

```text
chr1 → chr2
```

原来合格的 chr1 路径消失了。

我用当前源码做了只读的最小复现，结果确实是：

```text
只有 chr1：       unique，chr1，0.95
加入 chr2 尾巴： unique，chr1→chr2，1.00
```

### 为什么会这样？

当前实现先把 alignment segments 建成有向图：

- 能顺着 read 往后接的片段之间连边；
- 从没有前驱的根节点出发；
- 只有走到没有后继的叶子，才保存路径；
- 最后才检查覆盖度。

于是，chr1 一旦有了 chr2 后继，就不再是叶子。

虽然停在 chr1 时已经满足覆盖度要求，但算法没有把“在这里停下”作为候选输出。

这不只是漏了正常单臂路径。更一般地，它也可能漏掉合格的非最长路径，或从非根节点开始的合格解释。

问题位置：`fin/fusion/paths.py:170`。

### 为什么这是精度漏洞，而不只是一个枚举小问题？

因为下游的竞争裁决只能在它收到的候选之间进行。

假设 BCR→ABL1 模板最后验证通过。我们本来希望这意味着：

> 它不仅能解释 read，而且没有同样合理的普通位置解释与它竞争。

但如果正常路径在枚举阶段被删掉，实际结论就变成：

> 在只剩融合解释的候选集合里，融合解释通过了验证。

这两句话的证据强度完全不同。

可以类比成一次实验对照：

> 本来要比较处理组和正常对照。后来因为处理组多测到了一个尾部信号，就把正常对照从统计表里删掉了。

之后再精细地计算处理组分数，也不能补回缺失的对照。

所以这是一个**可能抬高假阳性风险的算法缺陷**。不过，最小复现证明的是“正常假设确实会丢失”，不是证明这个合成例子一定会通过全部后续门槛，更不是已经证明 K562 的某个具体调用因此是假阳性。

对于三个真实例子，它的重要性分别是：

- **BCR–ABL1**：正确阳性仍应当经得住完整竞争集合，而不是依赖竞争者缺席；
- **BAG6–SLC44A4**：附近位置竞争之外，普通单基因或其他位置的解释也不能被提前删掉；
- **chrM**：当前线性表示已经容易制造分段路径，更需要保留合理替代解释，而不是让“多一段”天然占优。

## 2. BAG6–SLC44A4 三行：不同分子没有在回答同一道题

### 先看输出是什么

冻结表里有三个 BAG6–SLC44A4 模型：

| 代表连接位置 | 模型长度 | 唯一支持分子数 |
|---|---:|---:|
| `31651655 → 31865784`，负链 | 1424 bp | 4 |
| `31651655 → 31865778`，负链 | 1422 bp | 2 |
| `31651655 → 31865784`，负链 | 1357 bp | 2 |

它们都可以显示成 `BAG6:e2>SLC44A4:e15`，但模型范围、坐标替代项和支持分子并不相同。

**同一个外显子级名字，不等于同一个精确序列；三行也不能直接等价成三个生物学事件。**

其中，支持 `31865778` 那一行的两条分子是：

- `831bd9d4…`
- `9e44b766…`

### 冻结的结点判定到底写了什么？

逐条查 `junction_corrections.jsonl`，这两条分子的融合结点都是：

```text
reason = indistinguishable_coordinates
selected_positions = null
```

也就是局部结点评分**没有决定一个唯一坐标**。

| 分子 | 原始观测结点 | 实际候选中右端坐标的范围 | margin |
|---|---|---|---:|
| `831bd9d4…` | `(31651656, 31865775)` | `31865775–31865778` | 2.0 |
| `9e44b766…` | `(31651655, 31865779)` | `31865776–31865781` | 0.0 |

这里说的范围是实际候选的最小到最大值，并不表示中间每个整数都被提名。

关键是：

**另一个模型使用的 `31865784`，没有进入这两条分子的候选集。**

对第一条分子，它离原始观测的右端位置差 9 bp；对第二条差 5 bp，都超出自己的 ±3 bp 提名范围。

具体证据在：

- `experiments/fusion/_k562_rep4_seq/fusion/junction_corrections.jsonl:7539`
- `experiments/fusion/_k562_rep4_seq/fusion/junction_corrections.jsonl:8988`

### 为什么局部未决，最后还能成为模型支持？

因为程序会保留近乎打平的坐标组合，再做完整 stitched-template 验证。

这两条分子最终都得到：

```text
status = supported_path
reason = coordinate_ambiguity
```

第一条保留 3 个 selected path，第二条保留 4 个。

所以不是“校正器已经强烈认定 31865778”，而是：

> 在各自有限的候选集合内，完整路径支持 BAG6→SLC44A4，但仍有局部坐标歧义。

模型层的 `support_unique=2` 也不能被翻译成“两个分子都唯一证明了这个碱基位置”。它是当前报告模型和候选关系下的唯一归属，仍然受前面候选是否完整的影响。

### 为什么不同候选集会让结果不可直接比较？

假设想判断两个位置：

- A：`31865778`
- B：`31865784`

公平的流程应当让每条有信息的分子都比较 A 和 B：

| 分子 | 对 A 的解释能力 | 对 B 的解释能力 | 结果 |
|---|---|---|---|
| read 1 | 算过 | 算过 | 支持 A / B / 未决 |
| read 2 | 算过 | 算过 | 支持 A / B / 未决 |

目前却可能是：

- 第一条分子只在 775 附近挑最佳；
- 第二条只在 779 附近挑最佳；
- 其他分子在 784 附近挑最佳。

然后把各自“局部胜出或局部兼容”的结果放到一起，当成模型之间的区别。

这就像：

> 一组人只尝了甲店和乙店，另一组人只尝了丙店和丁店；不能根据两组选出来的“最好吃”，判断甲店与丙店谁更好。

更不能说：

> read 1 支持 A，所以它反对 B。

它根本没看过 B。

这里的“不可比”不是说完全不能汇集不同 read，而是说：**在候选集合不一致时，不能把某个局部结论解释成对全事件族替代模型的排他性裁决。**

### 为什么 margin = 6 不是强置信？

当前局部 DP 的基本分数是：

```text
match：+2
mismatch：−4
```

在其他条件相同的情况下，一个碱基从 mismatch 变成 match，差值就是：

```text
2 − (−4) = 6
```

因此，6 分可能只相当于一个碱基的匹配差异。

它不是：

- 6 个独立观测；
- Phred 6；
- 某个已校准的后验概率；
- 已证明低于某个假阳性率的置信门槛。

实际 DP 还有 indel 和对齐路径变化，所以不能把所有 6 分都解释成恰好一个错配；但这个量级足以说明，**“超过 6”不是“强生物学置信”的同义词**。

更重要的是，即便局部 margin 很大，也只能证明“胜过比较过的候选”，不能证明胜过从未进入候选集的 `31865784`。

这也适用于 BCR–ABL1 和 chrM：高分可以支持模板解释，不能替代竞争集合的完整性，更不能替代机制判断。

## 四、按优先级的改进清单

这里的 kill test，指的是：**如果一个方案连这个反例都过不了，就不应被当作问题已解决。** 不是只看总模型数有没有变好看。

### 1. 第一优先级：修复 `find_read_paths` 的假设丢失

**改什么**

让所有满足覆盖度和连接约束的路径都有机会进入裁决，包括：

- 已经合格、但仍有后继的前缀路径；
- 从非根节点开始的合格路径；
- 正常单臂解释；
- 不因新增一段可连接 alignment 就消失的原有解释。

同时保留有界搜索。若候选过多，应该明确 `unresolved`，而不是静默截断后把剩下的路径当唯一答案。

**为什么**

这是候选完整性问题，是所有后续置信判断的地基。

先修它，BCR–ABL1、BAG6 和 chrM 的后续裁决才有同一套可信的竞争前提。

**Kill test**

- 复现 `950M50S` 加 `950S50M`，加入尾巴后 chr1 正常路径必须仍在；
- 增加合格的中间停止路径、非根起点路径用例；
- 改变 segment 输入顺序，结果不应改变；
- 超限必须明确弃权；
- 做端到端负例：正常解释仍有竞争力时，不能只因为多了一个尾部匹配就获得无竞争的融合支持；
- 回放 BCR–ABL1，检查真实阳性是否仍能成立，而不是仅追求候选数下降。

### 2. 第二优先级：给环状 contig 正确的解释，不是一刀切过滤 chrM

**改什么**

对明确指定为环状的 contig，识别符合方向和端点几何的跨原点路径，标记：

```text
circular_reference_origin_spanning
```

必要时引入跨原点连续模板，作为正常拓扑解释参加竞争。

**为什么**

12 个 chrM 模型里，只有 6 个具有跨参考原点的几何。

例如：

```text
chrM:16569:+ → chrM:0:+
```

以及负链方向：

```text
chrM:0:- → chrM:16564:-
```

这两类能用参考末端与开头相邻来解释，也包括支持 91 和 390 的两个高支持模型。

但还有例如：

```text
chrM:12134:+ → chrM:13867:+
chrM:9999:+ → chrM:13867:+
```

它们不是跨原点，不能用“线粒体是环状”一句话解释掉。

所以：

- 把 12 个都当异常融合，不对；
- 把 12 个都说成跨原点，也不对；
- 把 chrM 全部删除，丢失了需要分别判断的结构。

这个标签表达的是**参考拓扑解释**，也不意味着测到的 RNA 分子本身是环状 RNA。

**Kill test**

- 在冻结 12 个 chrM 模型中，识别出那 6 个跨原点模型，而不是全标；
- 正、负链方向都测；
- 非原点内部连接不误标；
- chrM 与核染色体的连接不能仅因含 chrM 就被豁免；
- 对合成环状参考改变线性化起点，生物学解释应保持一致；
- BCR–ABL1 和 BAG6 的分类不应受影响。

### 3. 第三优先级：事件族共享候选集，分开报告事件和异构体支持

**改什么**

先把合理属于同一事件族的分子和模型组织起来，再汇集其候选坐标与必要的结构替代项。

对 BAG6–SLC44A4，至少要让相关分子在适当的统一框架下都比较过：

```text
31865778
31865784
```

以及其他有依据的局部替代位置。

重点不是简单把 ±3 改成 ±10，也不是只扩大一个 registry：**如果后面仍按每条分子的原始坐标重新裁掉候选，问题还在。**

在同一分子内部，对不同候选保持 query 窗口和评分条件可比；不同分子之间汇集偏好和歧义，不直接把长度、质量不同的原始分数当同一种置信量。

同时拆开报告：

- 事件族支持度；
- 特定外显子结构的支持度；
- 精确坐标或坐标等价类的支持度；
- 无法区分的兼容支持。

**为什么**

两条分子可以明确支持“BAG6 接到了 SLC44A4”，却不足以决定是 778 还是 784。

这不是没用的证据，而是**支持粒度比一个精确模型更粗**。

BCR–ABL1 也需要同样区分：“支持 BCR–ABL1 事件”和“区分某个具体剪接异构体”不是同一个计数。chrM 则不能把所有不同内部结构统统归成一个事件，只因为染色体相同。

**Kill test**

- 对 `831bd9d4…`、`9e44b766…`，日志中必须能看到 `31865784` 被比较，或给出明确、可解释的不可评分原因；
- 改变分子处理顺序或原始提名来源，不应让共同候选无故消失；
- 同一序列的微同源坐标歧义应保留为等价或未决，不能强行选唯一；
- 真正不同的内部剪接异构体不能被多数票抹平；
- 不能为了共享候选，把没有完整分子支持的 A→B 和 B→C 拼成 A→B→C；
- 修复后的 BAG6 可以合并、分开或保持未决，验收目标是比较公平，不是预设“必须合成一行”。

### 4. 第四优先级：把证据强度、几何和机制拆成三个独立轴

**改什么**

不要让一个分类同时承担三个不同问题：

| 轴 | 问题 |
|---|---|
| 证据强度 | 几条不同分子？正常解释是否被排除？坐标是否明确？ |
| 几何 | 同染色体还是跨染色体？方向是否共线？是否跨参考原点？ |
| 机制解释 | readthrough、异常剪接、DNA 重排、技术嵌合，还是未知？ |

当前 chain 逻辑会把 readthrough 归到 `readthrough_or_splicing`，而不进入 `supported_rna_fusion`。这样把“长什么样”与“证据强不强”绑在了一起。

**为什么**

完全可以同时成立：

> 这个跨基因 RNA 连接有较强分子证据；它的几何符合 readthrough；但机制尚未独立验证。

对应三个例子：

- **BCR–ABL1**：RNA 证据支持，几何为染色体间；已知阳性背景不能替代新样本的独立机制证据。
- **BAG6–SLC44A4**：RNA 路径有支持，负链逆序几何；坐标仍有歧义，机制未知。
- **chrM 跨原点**：可有很高分子支持，但几何由环状参考连续性解释，不应因此获得“异常融合”含义。

**Kill test**

- 在分子证据不变时，仅改变几何标签，支持计数不应变化；
- 高支持 readthrough 必须能够表达“RNA 连接证据强”，而不是被类别名字压成低证据；
- 低支持染色体间候选不能仅凭跨染色体就得到高置信；
- chrM 原点标签只改变拓扑解释，不删除原始分子证据；
- 输出中机制未知应当是正常、可接受的状态。

### 5. 第五优先级：报告真实 motif，但明确它不是机制分类器

**改什么**

输出具体的 donor/acceptor 二核苷酸，例如：

```text
GT–AG
GT–CA
```

而不只给 `canonical=true/false`。

还要说明：

- 使用哪套参考；
- 采用哪个坐标；
- 按哪个转录方向取序列；
- 若坐标未决，不同候选的 motif 是什么。

代码已有按臂方向取二核苷酸的函数，可以把这一信息显式带到报告层。

**真实例子**

我按冻结运行的参考和代表坐标核对：

| 连接 | 参考 motif |
|---|---|
| BCR `23290413` → ABL1 `130854063`，正链 | `GT–AG` |
| BAG6 `31651655` → SLC44A4 `31865784`，负链 | `GT–AG` |
| BAG6 `31651655` → SLC44A4 `31865778`，负链 | `GT–CA` |

这说明 motif 值得报告：BAG6 两个近邻坐标，生物学解释所依赖的局部参考序列不同。

但不能反过来说：

> 784 是 GT–AG，所以它一定正确。

那会把注释或 motif 偏好冒充 read 证据。正确做法仍是让同一分子公平比较这些候选。

**为什么要提醒 ascertainment bias？**

因为当前候选提名已经使用了 canonical motif。

因此，如果最后发现输出中的 canonical motif 比例较高，这个比例部分是由“什么候选有资格进入比较”决定的。

不能先用 GT–AG 提名，再把输出富集 GT–AG 当作完全独立的真实性证明。

对于 chrM 跨原点连接，motif 更不应成为判断环状参考连续性的门槛。

**Kill test**

- 正、负链用例必须取到正确的实际二核苷酸；
- BAG6 两个代表坐标必须分别报告 `GT–AG` 与 `GT–CA`；
- 只增加 motif 展示，不应改变原有分子支持；
- 同序列坐标替代项不能因显示排序变成“已解决”；
- 如果要研究 motif 富集，必须另外设计不受同一 motif 提名规则支配的比较背景。

对应函数：`fin/fusion/junctions.py:42`。

### 6. 第六优先级：稳定的事件族 ID、去重支持度；之后再做 CDS 感知的 ORF

**先改什么**

建立独立于具体模型行的事件族 ID，能把相关模型组织在同一层级下，同时保留结构差异。

支持度按 read ID 去重，而不是把模型表中的各列相加。

BAG6 的三行当前各有 4、2、2 条 unique read，三组 ID 在这份产物中不重叠，集合共有 8 条。但这只能描述：

> 当前三行所收录的 unique read ID 合集有 8 条。

它不是已经完成共享候选裁决的“8 条确认事件支持”，也不是 8 条都证明同一个精确异构体。

尤其不能把同一条 read 在多个模型里的 compatible、nearby 记录再加一遍。

BCR–ABL1 的四个来源 chain 也不代表四个事件。chrM 的原点附近几个模型，同样需要在合理的族定义下组织，而不是简单逐行计数。

**为什么 ORF 应排在后面？**

当前 fusion 转录本模型索引主要保存：

- transcript ID、gene ID；
- 染色体和链；
- 外显子结构。

**没有保存足够的 CDS/phase 信息用于可靠的 CDS 感知判定。**

而且现有 FASTA 是参考投影，不是样本 consensus。

因此，对现在的 FASTA 找一个最长 ORF，不能直接回答：

- 融合是否保持原有阅读框；
- 采用哪个转录本的 CDS 起点；
- 结点前后的编码相位是否相容；
- 样本是否有改变阅读框的 insertion/deletion；
- 预测蛋白是否真实表达。

对 BCR–ABL1，也不能因为名字是已知阳性，就把程序尚未建模的 CDS 结果说成已经由这条流水线推导出来。

对 BAG6，坐标和模型还未充分裁决时，过早输出蛋白更容易制造虚假的确定性。chrM 则还需要匹配其相应的注释和翻译语义，不能机械套同一流程。

**Kill test**

- 同一分子支持多个兼容模型时，事件族支持只能增加一次；
- BCR–ABL1 不因来源 chain 数量变化而变成多个事件；
- BAG6 可在同族内保留多个模型，但不重复加票；
- 明显不同的结构不能仅因基因对相同而误合并；
- ORF 功能必须用已知 in-frame、frameshift、缺 CDS、负链和端部不完整用例验证；
- 信息不足时输出未知，而不是默认 in-frame。

### 保持不变的两件事

**第一，signal 验证保持关闭。**

冻结 K562 全库结果的状态是 `not_scored`，是序列层面的分析，不应把它讲成已获得电流信号验证。

现在先不打开 signal，原因不是“信号肯定没用”，而是：

- signal 不能把已经被路径枚举删掉的正常竞争者找回来；
- 不能证明一个从未被提名的 BAG6 坐标输掉了竞争；
- fusion signal 的阈值和准确率还没有足够独立验证；
- 现有 signal 后端并不是实验性的 raw-DTW 最小 SSE 规则，不能混为一谈；
- 同时改候选、序列裁决和 signal，会让结果变化难以归因。

先把竞争集合和证据语义修好，再独立评估 signal 是否确实提供增益。

**第二，250 bp clip 提名阈值保持不变。**

这是控制候选规模的入口阈值，不是“只有超过 250 bp 的融合臂才允许存在”。

真实数据中，100 bp 阈值容易把 dRNA 的 adapter/poly(A) 末端大量提名，既往测量约影响 8.6% 的 primary records，并曾触发当时的候选上限。

保留 250 bp 的理由是：

- 先避免把大量普通末端带入昂贵的全基因组重比对；
- 仍有 SA/supplementary 和跨基因剪接等其他提名入口；
- 此次两个核心缺陷都不是 clip 阈值造成的。

但也应承认其代价：**如果一个真实事件只有不足 250 bp 的 clipping，而且没有其他提名线索，可能被漏掉。** 保持阈值不变是当前有依据的工程选择，不是宣称它已被证明最优。

---

## 五、一句话总结

**现在的 fusion 输出可以用来提出和组织有逐分子证据的 RNA 嵌合候选、恢复 BCR–ABL1 这样的已知阳性，并提供可追溯的参考投影序列供后续验证；但不能把每一行直接当成独立且已确证的融合事件，更不能据此宣称全库精度、DNA 重排机制、精确异构体或蛋白功能已经确定。**
